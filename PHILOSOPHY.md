# The Hermes Operating Principles

*Why this agent ends up solving everything — and how to use it that way.*

Hermes is not a chatbot that answers questions. It is an agent with hands:
a terminal, files, a browser, messaging, memory, and the ability to install
its own new powers. People who get spectacular results from it are not doing
anything secret — they just act like the list below is true, because it is.

## 1. Give it the whole machine, not a chat box

The difference between "my AI suggested some steps" and "my AI fixed it" is
access. Let it run commands, read and edit files, drive the browser, connect
your accounts. Every door you open turns it from an advisor into an operator.

## 2. It remembers — permanently

Memory and skills make the second time trivial. Corrections stick, preferences
stick, a fix that took an hour becomes a one-sentence request next time. Teach
it once on purpose: "remember that…", "from now on…", "never do X".

## 3. It can upgrade itself

Needs to read PDFs? New skill. A service it doesn't support? MCP server.
A feature that doesn't exist? Plugin, or a small script it writes itself.
"Can you do X?" is the wrong question — ask "what would it take to do X?"

## 4. Real results, not vibes

"Done" means: the command ran, the API answered, the page loads, the file
exists. Every claim should come with the evidence attached. Demand that
standard and the whole relationship changes.

## 5. Fix, verify, then report — and iterate when it fails

The loop is: diagnose → act → verify → tell you plainly. When something
breaks, the next attempt should be different (a different route, a fallback,
a workaround) before it ever says "I can't". Escalate only after it has
genuinely tried.

## 6. One automation at a time, compounded

Don't plan a grand system. Take your most annoying repetitive chore, automate
that one thing end-to-end, live with it a week, then take the next one.
Twelve weeks later half your week runs itself.

## 7. Ask anything — and never ask "can you"

Describe the goal in plain words: a photo, a voice note, half a sentence
("deal with this"), a language switch mid-thread. Then ask the meta questions
out loud:

- "What can you do for me?"
- "What should we automate next?"
- "Look at what we've been working on — what am I still doing manually?"

The agent can see its own capabilities and your history. Let it write its own
job description.

## 8. Let it parallelize and delegate

Big jobs get split: research runs in parallel, workers go off and come back
with summaries, drafts get attacked from three angles. You supervise; it does
the legwork. Ask for the plan first, then say go.

## 9. When it's stuck, it's usually a setup problem — fix the setup

Nine "I can't do that" moments out of ten are missing plumbing: a capability
not enabled, a key not connected, a version too old, a permission not granted.
The fix is mechanical. Ask "what exactly are you missing?" — then unblock it
together. This is why kits like this one exist.

## 10. Every session makes it a little better

Skills accumulate, memory compounds, your corrections become rules. The agent
you talk to next month is measurably better than today's — as long as you
keep correcting it in the moment instead of giving up quietly.

---

**The one-sentence version:** treat it like a capable operator with full
access, memory, and a habit of verifying its own work — and it will keep
surprising you with what it fixes that you never had to ask about twice.
